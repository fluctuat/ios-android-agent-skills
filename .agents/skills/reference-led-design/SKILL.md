# Reference-led native design

- For a new screen or substantial redesign, encourage a small set of user-chosen
  Apple/native, SwiftUI, Material/Compose or reference-library screens. Do not
  turn a small bug fix into compulsory design research.
- Inspect the actual reference flow before borrowing a pattern. An inaccessible
  link or remembered screenshot cannot support a claim of design fidelity.
- Transfer hierarchy and interaction patterns while keeping native navigation,
  keyboard and accessibility conventions. Similar screenshots do not imply the
  same control behavior across iOS and Android.
- Treat older samples as pattern references unless their APIs and requirements
  are verified against the current platform. A reference app's choice is not a
  platform requirement.
- Use a labeled concept for design proposals and actual rendered captures for
  implementation review. Keep those two kinds of evidence visibly distinct.
